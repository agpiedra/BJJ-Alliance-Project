## What was actually verified, not just rendered once

This is the second verification pass. Round 1 (see git history of this file) already fixed a container-query sidebar-collapse bug and an item-count typo. Round 2, against fresh owner feedback, found and fixed four more real defects by loading every section in a real Chromium browser rather than trusting the markup:

1. **Section D's desktop Overview/Organizations/Admins links were completely invisible.** Same root cause as round 1's Section A/C bugs, one instance I hadn't checked yet: `preview.css`'s `@container (max-width: 720px) { .only-wide { display: none !important; } }` was firing because the box's width inside the 2-column `.grid2` was under 720px, and the links carry `.only-wide`. Fixed with `container-type: normal` on both Section D desktop `.stage` boxes, same pattern as before. Re-verified: all three links visible in both themes.
2. **Every role example now matches production exactly, including the switcher's two real states** (`src/components/staff-sidebar/academy-switcher.tsx`, traced directly, not assumed): a clickable two-line dropdown (bold current selection + "View all locations" hint + chevron) when there are 2+ branches, versus plain read-only text (a dot + the branch name, no chevron, not clickable) for DIRECTOR/INSTRUCTOR always, and for ADMIN too at exactly one branch — "an Owner sees the location's name like a director does," per the component's own comment. Section B now shows **four** scenarios instead of two: ADMIN/2+ branches, ADMIN/1 branch, DIRECTOR (6 items, no Schedule), INSTRUCTOR (3 items) — preserving the original ADMIN single- vs. multi-branch distinction the first round's prototype had erased.
3. **A real layout bug found while fixing item counts: every phone "open" sheet box was too short to show its own footer.** `.app` has `min-height: 640px` and the open sheet is absolutely positioned `top:0;bottom:0` inside it, so "Theme"/"Sign out" are pinned to the bottom of a 640px-tall sheet regardless of how few nav items precede them — a box shorter than ~640px (several were, at 420-480px) silently cropped the footer, making sign-out unreviewable. Fixed by raising every affected phone-sheet box (Sections B, C, D, E) to 650px. The one deliberate exception: ADMIN's first "open" view (9 items) is intentionally still short enough to show the real internal scrollbar, with a dedicated **scrolled-to-bottom** companion box immediately next to it so the footer is reviewable without relying on a scrollbar, per the request that prompted this round.
4. **Section E previously put one fictional name in both the breadcrumb (organization) and the switcher pill (branch), implying they were the same value.** They are two different real props (`orgName` vs. `academyLabel` on `staff-top-bar.tsx`, traced directly) and are never interchangeable. Section E was split into three distinct, labeled demonstrations with two distinct fixtures — organization "Academia Internacional de Jiu-Jitsu Río Grande" (E1, breadcrumb only) and branch "Alliance Heredia" / "Sede San Pedro – Mall San Pedro, Local 204" (E2/E3, switcher and avatar role line only) — so nothing implies the org name is readable from the switcher or the avatar menu. E1 also confirms the breadcrumb's header genuinely grows (`.topbar` uses `min-height`, not a fixed height) when wrapped, with no overlap of the theme toggle or avatar.

## Verification limits — what this prototype review does and does not prove

This is static markup with no application logic, no `SidebarProvider`/`Sheet`/`BrandingScope` React code, and no real routing. What was verified: visual rendering (no clipping/overflow, correct item counts per role, correct real strings in both languages, correct switcher affordance per role/branch-count), that the tenant-colour bug's proposed fix direction is visually convincing, and that long/wrapping content (both the organization name and, separately, a branch name) doesn't overlap adjacent controls.

**What this does NOT prove:** the real `Dialog.Portal` `container` fix for the §7.10 bug (a code change, not yet written), real `SidebarProvider`/`useIsMobile()` behavior at the real 768px breakpoint, real focus management when the sheet opens/closes, or real avatar-dropdown/organization-switcher wiring. Those are implementation-phase concerns, verified against real code the same way every prior MATROOM phase's own verification worked, once D6 and the open items below are decided.
