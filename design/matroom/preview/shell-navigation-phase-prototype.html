Shell & navigation — D6 proposal

The staff and platform shells' sidebar, top bar and phone navigation chrome. D6's recommended pattern (top bar + menu button + sheet, no bottom navigation) made concrete against the real nav structure, real role-visibility rules and real tenant branding — plus the documented phone-sidebar tenant-colour fix.

Illustrative sample data. "Harbor Jiu-Jitsu" (a fictional tenant with an invented orange theme) and all names/counts are invented for this prototype. Every nav label, role group and visibility rule shown is copied verbatim from the real app's current src/components/staff-sidebar/nav-items.ts and messages/en.json/es.json — not invented. No app file, token, component or route was changed to build this.

What's being decided

D6 (DESIGN.md): "Phone navigation: top bar, menu button and sheet for student and staff, no bottom navigation, two new strings ('Menu', 'Close menu')."

This prototype proposes D6 applies to staff and platform shells too (student portal already shipped this pattern in the portal phase). Concretely:

  • Desktop: unchanged in substance from what exists today — collapsible left sidebar (src/components/ui/sidebar.tsx, already built, already themed) + a persistent top bar.
  • Phone: the sidebar becomes a dedicated sheet with its own header (brand + close button) and a footer for secondary actions (theme, sign out) — not a bare reuse of the desktop sidebar's own markup, which is what the very first Phase-1 preview showed for staff and what today's real `Sheet`-based mobile sidebar still does. This brings staff into parity with the student portal's own already-shipped sheet pattern (section B below), per D6's own "student and staff" wording.
  • Two new strings: "Menu" / "Close menu" (shellNav.menuOpen / shellNav.menuClose proposed keys) — the only new copy this phase needs.
  • Platform shell currently has none of this — section D shows it gaining the same top-bar + sheet pattern, scaled down to its 3 real nav links and single role.

C — Tenant-colour fix (DESIGN.md §7.10)

Confirmed root cause (traced in the real code, not assumed): src/components/ui/sheet.tsx's SheetContent wraps in SheetPortal → Base UI's Dialog.Portal, which renders into document.body by default. BrandingScope (src/components/branding/branding-scope.tsx) overrides --sidebar*/--brand-gold* via a <style> block scoped to a [data-branding="org-…"] wrapper in the DOM — correct for the desktop sidebar (a real DOM descendant) but the portaled mobile sheet is a React-tree descendant only, not a DOM one, so the override never reaches it. Proposed fix (implementation phase, not this one): pass Base UI's Dialog.Portal a container ref pointing at a node rendered inside BrandingScope, so the portaled sheet becomes a real DOM descendant of the branded wrapper again.

E — Spanish, long labels, and the avatar/org menu

Spanish nav labels (real strings from messages/es.json), role DIRECTOR throughout (6 items, read-only branch switcher). Organization and branch are deliberately different fixtures here — the breadcrumb shows the organization's name (orgName, real prop on staff-top-bar.tsx); the switcher pill and the avatar's role line show the branch name (academyLabel) — two different real values, never interchangeable, so nothing here should be read as "the org name is available from the switcher or the avatar."

E1 — breadcrumb: growing header, no control overlap

Organization only, avatar closed. .topbar uses min-height (not a fixed height) with align-items:center, so wrapping the breadcrumb to 2 lines grows the whole bar instead of clipping or sliding under the theme toggle / avatar — both stay fully visible, vertically centered against the taller bar.

F — Organization switching (preserved, not redesigned)

A user who belongs to 2+ organizations (not branches) is routed to the real, already-shipped full-page /select-organization screen (Phase 1) — this phase does not touch that mechanism or add an in-shell org switcher. The switcher pill shown above is the branch/academy switcher (AcademySwitcher, already in production, unrelated to multi-organization membership) — same component, unchanged behaviour, just inside the new sheet header instead of only the desktop sidebar header.

What this is not

No app file, token, component or route was changed to build this. Every colour is a real token or a real org's stored value (the orange "Harbor Jiu-Jitsu" theme is fictional, its hex values invented but applied exactly the way BrandingScope applies a real one). "Panel"/"Alumnos"/"Horario" etc. are the app's real current strings, not reworded for this prototype. Screen content (dashboard tiles, student tables, etc.) is explicitly out of this phase's scope — the stub pages above exist only to show the shell around them.
